## Why

apiroute can generate clients from OpenAPI/Swagger specs and WSDLs, but not from GraphQL. Today a GraphQL client is hand-written `graphql_route` methods that return plain dicts. The response types, which GraphQL fully knows, are lost, and nothing keeps a client repository in step with the API as the schema changes. 1.7.0 and 1.8.0 built the runtime (`graphql_route`) and the schema loading and validation (`graphql_schema`). Code generation is what's left: it turns hand-written operation files into a typed client that client repositories regenerate on a schedule, as they do for REST and SOAP.

GraphQL can't follow the OpenAPI model of "one method per endpoint, generated from the spec". The caller chooses the response shape, so a generator that emits every field would produce huge queries and hit cost limits. The design that works (genqlient, ariadne-codegen, graphql-codegen) is **operations first**: the user writes `.graphql` operation files, and the generator validates them against the schema and emits one typed method per operation. The result models are shaped by what each query selects, not by the schema's types.

## What Changes

- **New command `apiroute generate graphql <schema> --operations <dir> -o <package>`.**
  - `<schema>` is an SDL file, a `.json` introspection result, or an http(s) endpoint to introspect, with `--header "Name: value"` for auth.
  - `<dir>` holds `.graphql` files of named operations and fragments. Files at its top level become root-client methods, and each subdirectory becomes a `Section`, like OpenAPI tags.
- **Every operation is validated against the schema before anything is written.** Generation fails with every problem across all files, each with its file, line and column, and leaves the output directory untouched. Uses of deprecated fields are reported as warnings.
- **Dict layer (always):** one `graphql_route` per operation, with the document inlined (including the fragments it uses) and one parameter per variable. It returns the operation's `data` as a dict.
- **Typed layer (`--models`):**
  - pydantic result models shaped by each operation's selection set (`RepoResult`, `RepoRepository`, ...), honouring aliases, nullability, `@include`/`@skip`, fragments, and interfaces/unions (discriminated by `__typename`, which the generator adds where needed);
  - models for the input objects and enums the operations' variables use;
  - typed methods that take input models and return result models through the existing `TypedClient`.
- **Scalar mapping:** built-ins map to `int`, `float`, `str` and `bool`. Custom scalars map to `Any` unless `--scalar DateTime=datetime:datetime` maps them to an importable type.
- **Reused options:** `--endpoint URL` (split into `base_url` and the route `path`), plus the existing `--client-name`, `--base-class`, `--models` and `--no-format`, with the same regeneration and "Generated by apiroute" marker rules as the other formats.
- **New command `apiroute fetch-schema <endpoint> -o schema.graphql [--header ...]`.** It introspects an endpoint and writes SDL (or JSON for `.json`), giving client repositories a readable, diffable `specs/` snapshot.
- **The `codegen` extra gains `graphql-core>=3.2`.**
- **The client-repository skill (`.agent/skills/apiroute-client.md`)** learns `format: graphql`, an operations directory per API, and introspection headers.

Not in scope: subscriptions, generating operations automatically from the schema, fragment models as shared base classes, persisted-query manifests, and pagination helpers.

## Impact

- **New:** `src/apiroute/codegen/graphql/`, which holds:
  - the reader that builds an `ApiDefinition` from a schema and operations;
  - the selection-set → `Model` mapper;
  - the operation collector;
  - schema fetching.
- **Changed:**
  - `codegen/cli.py`: the `graphql` format, its options, and the `fetch-schema` command.
  - `codegen/api_definition.py`: `Operation.graphql` metadata and the `"variable"` parameter location.
  - `DictClientEmitter` and `ModelsClientEmitter`: they emit `graphql_route` methods.
  - `PackageEmitter`: its source line names the schema and operations.
- **Shared loading:** `graphql/graphql_schema_loader.py` exposes file loading so runtime validation and codegen share one loader.
- **Generated output is a public interface.** This adds a new format without changing OpenAPI or WSDL output. `tests/codegen/` covers the GraphQL output, including importing and calling a generated package and running ruff on it.
- **Dependencies:** `graphql-core>=3.2` joins the `codegen` extra. Runtime dependencies are unchanged.
- **Release:** `feat:` (minor).
